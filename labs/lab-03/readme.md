# Lab 03: Pair-Programming Problem Set (Kattis)

## Overview

* Work in **pairs (groups of 2)**.
* **One open laptop per group** (the “Driver’s” machine).
* Solve each assigned problem **on Kattis**.
* For each solved problem, **screenshot the “All test cases passed” page**.
* Use **whiteboards, paper, and TVs** to plan, trace, and project code as needed.

---

## Pair-Programming Rules

1. **Roles**

   * **Driver:** Types on the single laptop, voices thoughts.
   * **Navigator:** Reads the prompt, reviews logic, spots bugs, and guides the Driver.
2. **Rotation**

   * Switch roles **every 15–20 minutes** or **after each submission** - whichever comes first.
   
3. **Visibility**

   * Keep the code visible to both partners at all times (project on a TV when helpful).

---

## Workflow (Repeat per Problem)

0. Create a Kattis account with your URI email.

1. **Understand the prompt**: Read aloud; list inputs/outputs, constraints, and edge cases on a **whiteboard/paper**.
2. **Design**: Sketch a step-by-step approach, test with 2–3 sample cases you invent.
3. **Implement on Kattis** (Driver types): Start from a clean template; keep I/O strict.
4. **Self-test**: Run local/custom tests if possible; then submit to Kattis.
5. **Verify**: Wait for verdict; if not accepted, debug using your notes/whiteboard.
6. **Screenshot Proof**: Once **all test cases pass**, capture a **full screenshot** showing:

   * Problem name, your submission verdict (“Accepted”), and timestamp / run ID.
7. **Reflect (1–2 sentences)**: Note the key trick or edge case you handled.

> :warning: The use of LLMs such as ChatGPT is prohibited.
